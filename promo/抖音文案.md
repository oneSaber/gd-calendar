### 正文（直接复制）

```
做这个的起因很蠢：我一直传「广州,深圳」，结果珠海中山那 6 个城市一场都没采到，
还以为是自己抓漏了。修完之后顺手把它做成了一个正经项目。

它干的事：
1️⃣ 自动采集 —— 秀动（SSR 页面）、豆瓣同城（官方 RSS）、
   B站动态/会员购（浏览器渲染 + 抄它自己的 XHR）、微博搜索页
2️⃣ 中文文案解析 —— 「📅 2026.09.24 🕖 19:00 入场」「¥180起」
   「OPEN 18:30 / START 19:30」「参演团队：@A @B @C」这类自由文本，
   解析成时间/票价/场地/阵容的结构化场次
3️⃣ 实体归一化 + 三层判重 —— 同一场演出被多个来源收录时合并成一条，
   时间冲突不静默覆盖，而是并排显示 + 进人工复核队列
4️⃣ 输出 —— 网页日历（列表/月历/详情/筛选）+ REST API + .ics 订阅

三个能看出来的细节：
· 地偶 / 女子乐队 / ACG 是三个**互相正交**的标记，一个 ACG 女子乐队三个都为真
· 海报走后端代理（豆瓣图床没带 Referer 会返回 418，前端直接引用一定裂图）
· 置信度低于 0.8 的场次用虚线边框标「待确认」，标注来源，能回原站核对

合规上我划的线：不破解验证码、不注入登录 Cookie、不逆向签名（秀动的 crpsign、
大麦的 mtop、B站的 wbi 一律不做）；小红书和抖音实测都是登录墙，直接放弃；
单域名 ≥3 秒一次，豆瓣按其 Crawl-delay: 5 执行。
只存事实字段（时间/场地/乐队/票价）+ 显著回链，不整篇转载文案、不搬运海报原图。

开源仓库：gd-calendar（评论区置顶）

#开源项目 #Python #FastAPI #数据采集 #livehouse #广州演出 #深圳演出 #地下偶像 #ACG #独立开发
```
